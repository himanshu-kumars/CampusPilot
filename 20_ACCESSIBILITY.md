# CampusPilot — Accessibility Requirements

## Semantic structure
- Use one clear H1 per page.
- Use headings in logical order.
- Use semantic buttons for actions.
- Use links for navigation.

## Forms
- Every input has a visible label.
- Errors are associated with the corresponding field.
- Required fields are marked.

## Keyboard
All primary workflows must be usable without a mouse.

Keyboard users must be able to:
- open navigation
- submit forms
- close dialogs
- move through task lists
- complete tasks

## Focus
- Maintain visible focus indicators.
- Do not trap focus outside open dialogs.

## Color
Never use color as the only status indicator.

Examples:
"Critical" + icon + color.

## Screen readers
Icon-only buttons need accessible labels.

## Responsive
The application must remain usable at small widths without horizontal scrolling.
